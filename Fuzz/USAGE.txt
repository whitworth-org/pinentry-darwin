Fuzz/ — libFuzzer harnesses for the AssuanProtocol library
============================================================

NOTE: This file is intentionally a .txt rather than a .md because the
project's .gitignore excludes all *.md files except the top-level
README.md.

What's here
-----------

  Fuzz/Driver/driver.c
    C entry point that hands control to libFuzzer's
    LLVMFuzzerRunDriver(). Used by every fuzz target.

  Fuzz/<TargetName>/FuzzTarget.swift
    The actual fuzzing logic. Defines `fuzz<Module>Once([UInt8])` and
    `@_cdecl("LLVMFuzzerTestOneInput")`.

  Fuzz/<TargetName>/main.swift
    SwiftPM executable wrapper. Reads stdin, runs the fuzz function once.
    Used for replaying saved crash artifacts; excluded from the libFuzzer
    build path (the C driver provides main).

  Fuzz/<TargetName>/corpus/
    Seed inputs. One file per input.

  Fuzz/<TargetName>/findings/
    libFuzzer crash artifacts land here (`crash-<sha1>`).

The four targets
----------------

  PinentryFuzzLineCodec
    Round-trips arbitrary bytes through escape/unescape (both command-arg
    and data-line variants). Asserts byte equality after round-trip.

  PinentryFuzzCommand
    Throws raw bytes at Command.parse() plus isValidFingerprint and the
    Mnemonic.strip / sanitiseBody helpers.

  PinentryFuzzMnemonic
    Throws Unicode strings at Mnemonic.strip(). Asserts that strings
    containing no underscore are returned verbatim.

  PinentryFuzzResponse
    Encodes raw bytes through Response.data(SecureBytes(_:)).wireLines()
    and asserts the round-trip via LineCodec.unescapeFromDataLine.

Running
-------

  scripts/run-fuzz.sh                          # all four for 60s each
  scripts/run-fuzz.sh PinentryFuzzCommand     # one target, 60s
  scripts/run-fuzz.sh --time 600               # all four for 10 min each
  scripts/run-fuzz.sh PinentryFuzzMnemonic --time 30

Replaying a saved crash:

  swift run PinentryFuzzCommand < Fuzz/PinentryFuzzCommand/findings/crash-XXX

Toolchain requirements
----------------------

Apple's Xcode-bundled Swift does NOT ship libFuzzer (`-sanitize=fuzzer` is
unsupported on the Apple-shipped toolchain). The runner script works
around this by force-loading the libFuzzer runtime archive
`libclang_rt.fuzzer_no_main_osx.a` from one of these locations:

  - /opt/homebrew/Caskroom/codeql/*/codeql/swift/resource-dir/...
    (installed by `brew install --cask codeql`)
  - /Library/Developer/Toolchains/*  (open-source swift.org toolchains)
  - /opt/homebrew/opt/llvm/...

If your machine has the runtime elsewhere, set FUZZER_LIB to the
absolute path before invoking the script:

  FUZZER_LIB=/path/to/libclang_rt.fuzzer_no_main_osx.a scripts/run-fuzz.sh

Important caveat
----------------

Because the AssuanProtocol Swift code is NOT coverage-instrumented (Swift
on macOS does not have a stable `-sanitize-coverage` flag exposed), the
fuzzer behaves more like a high-speed random-mutation black-box fuzzer
than a true coverage-guided fuzzer. You will see this warning every run:

  WARNING: no interesting inputs were found so far. Is the code
  instrumented for coverage?

This is expected and not a bug in the harness. Throughput is excellent
(200K-500K execs/second) so coverage-blind random mutation still finds
real bugs (it has — see the existing crash artifacts in
Fuzz/PinentryFuzzResponse/findings/).
